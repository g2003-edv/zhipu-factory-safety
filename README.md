# 厂区智能安防监控系统

基于 YOLOv8 目标检测与智谱 GLM-4V 多模态大模型的厂区行人入侵检测 Demo：本地模型逐帧检测行人，
触发告警时调用云端模型做二次复核，自动留存告警截图与 CSV 日志。

## 技术栈

Python 3.9+、Ultralytics YOLOv8、OpenCV、Pandas、智谱 AI GLM-4V 多模态接口

## 核心功能

1. 多源视频输入：按顺序尝试多个摄像头源（本机摄像头 / 手机 WiFi 摄像头 / RTSP 地址），自动重连
2. YOLOv8 实时行人检测，输出检测置信度与目标框数量
3. GLM-4V 云端二次复核，过滤光影、杂物、树枝等造成的无效误报
4. 告警抑制：同一摄像头 60 秒冷却窗口 + 连续帧去重，避免按帧调用付费接口
5. 云端不可用时自动降级为仅本地 YOLO 告警，主循环不中断，并在终端打印明确警告
6. 告警截图按“毫秒 + 帧号”命名，CSV 日志记录复核来源、模型原始回复与错误信息
7. 退出时输出运行时长、处理帧数、实测平均 FPS 与告警/抑制次数

## 环境依赖安装

```bash
python -m venv venv
source venv/bin/activate      # Windows: venv\Scripts\activate
pip install -r requirements.txt
```

首次运行会自动下载 `yolov8n.pt` 权重到当前目录（约 6 MB）。离线环境可自行下载后通过
`YOLO_WEIGHTS` 指向本地路径。

## 配置

所有配置从环境变量读取，也支持同目录下的 `.env` 文件（复制 `.env.example` 为 `.env`）。

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `ZHIPU_API_KEY` | 无（**必填**） | 智谱开放平台 API Key。缺失时程序启动即报错退出 |
| `GLM_MODEL` | `glm-4v-plus` | 云端复核模型名，可改为其他视觉模型 |
| `CAMERA_SOURCES` | `0` | 摄像头源，逗号分隔按顺序尝试，例如 `http://192.168.1.50:8080/video,0` |
| `ALERT_COOLDOWN` | `60` | 同一摄像头两次云端复核的最小间隔（秒） |
| `YOLO_WEIGHTS` | `yolov8n.pt` | 权重路径，首次运行自动下载 |
| `YOLO_CONF` | `0.35` | 行人检测置信度阈值 |
| `GLM_MAX_FAILURES` | `3` | 云端连续失败多少次后熔断为仅本地告警 |
| `GLM_TIMEOUT` | `30` | 单次云端请求超时（秒） |
| `SCREENSHOT_DIR` | `alert_screenshot` | 告警截图目录 |
| `LOG_CSV` | `告警日志.csv` | 告警日志路径 |
| `ENABLE_PREVIEW` | `1` | 是否显示预览窗口，无图形环境设为 `0` |

```bash
# Linux / macOS
export ZHIPU_API_KEY="your-key"
# Windows PowerShell
$env:ZHIPU_API_KEY="your-key"

python main.py
```

按 `q` 关闭预览窗口并退出；`Ctrl+C` 同样安全退出。

## 告警类型分类

| 类型 | 含义 |
| --- | --- |
| 0 | 环境干扰误报（光影、树枝、杂物等） |
| 1 | 真实厂区行人入侵告警 |
| 2 | 画面模糊、遮挡，需人工复核；模型回复无法解析时也归入此类 |

## 告警抑制与降级机制

- **冷却窗口**：同一摄像头在 `ALERT_COOLDOWN` 秒内最多发起一次云端复核；30 FPS 的输入不会每帧
  调用付费接口。被抑制的帧只计数，不写日志，退出时会汇总打印。
- **连续帧去重**：对画面做 64×48 灰度签名，与上次告警画面平均像素差小于阈值时视为同一事件的
  连续帧，跳过云端调用。画面持续 30 帧无行人后重新布防，允许同一场景再次告警。
- **降级**：网络异常、鉴权失败、响应结构异常都会让本条告警降级为「本地 YOLO 告警」
  （`复核来源=LOCAL_FALLBACK`），截图照常保存，终端打印警告；连续失败达到 `GLM_MAX_FAILURES`
  次后熔断，本次运行不再调用云端接口。

## 日志字段

`告警日志.csv`（UTF-8 with BOM，Excel 可直接打开）：

`批次ID`、`帧号`、`时间`、`图片路径`、`告警类型`、`类型说明`、`置信度`、`框数量`、
`复核来源`（`GLM` / `LOCAL_FALLBACK`）、`模型回复`（截断 120 字符）、`错误信息`（截断 120 字符）。

## 硬件与帧率

- YOLOv8n 在 CPU 上可实时运行，实际帧率取决于 CPU 型号、输入分辨率与同时运行的进程；
  程序退出时会打印本次运行的实测平均 FPS，请以该数值为准。
- 云端复核单次请求通常需要数秒，因此只在触发告警且通过冷却窗口时调用，不阻塞逐帧检测的
  统计逻辑（调用期间该帧的处理会等待，属预期行为）。
- 若帧率不足，可降低摄像头分辨率、调高 `YOLO_CONF` 或使用 GPU 版 PyTorch。
- 预览窗口依赖图形界面，服务器/容器环境请设置 `ENABLE_PREVIEW=0`。

## 隐私与仓库卫生

- 仓库不包含 `*.pt` 权重，首次运行时自动下载。
- 早期提交中的 `test.jpg` 实为 PNG 格式的私人院落照片（约 5 MB，代码未引用），已从版本库移除，
  本仓库不再分发任何实拍素材。
- 告警截图包含人脸等个人信息，`alert_screenshot/` 与 `告警日志.csv` 已被 `.gitignore` 排除，
  请按现场隐私合规要求保存与销毁。

## 已知限制

- 仅检测 COCO 数据集的 `person` 类别，不做人脸识别与身份判断。
- 冷却窗口内的重复事件不会重复写入日志，需要完整事件流时请调小 `ALERT_COOLDOWN`。
- 云端判定结果用于辅助人工复核，不构成自动化安全决策的依据。
